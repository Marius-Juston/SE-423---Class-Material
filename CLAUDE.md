# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Repository Is

Course material for **UIUC SE 423: Introduction to Mechatronics (Spring 2026)**, maintained by Marius Juston. It hosts:
- Lecture slides (`.pptx`) in `Lectures/Slides/`
- Lab handouts and homework assignments (LaTeX) in `Labs/` and `Homeworks/`
- TikZ figures in `Lectures/Figures/*.tex` (auto-converted to SVG by CI), and the source file of every picture embedded in the slides in `Lectures/Figures/{svg,png,jpg,gif,ppm}/` (see *Figures in the slides*)
- A GitHub Pages companion site in `site/` with interactive tools (color space visualizer, path planning, trajectory planning, LIDAR SLAM app) and a professor's guide (`site/professor_guide.html`)
- The README banner / social preview card in `.github/assets/` (generated by `make_repo_card.py`)

Plots and animations are generated in the companion repo [SE423Animations](https://github.com/Marius-Juston/SE423Animations) (usually checked out next to this one at `~/GitHub/SE423Animations`); their SVG outputs are copied into `Lectures/Figures/svg/` and the decks.

The CI pipeline (`.github/workflows/build-latex.yml`) compiles PPTX → PDF, LaTeX → PDF + HTML, and figures → SVG, then deploys to an `artifacts` branch.

## Build Commands

**Compile a single LaTeX file locally (TeX Live 2025+ required, run from the repo root):**
```bash
latexmk -pdflua -shell-escape Labs/Lab1.tex
```

**Full build (as CI does it, requires `-shell-escape` for minted):**
```bash
latexmk -pdflua -interaction=nonstopmode -file-line-error -halt-on-error -shell-escape -outdir=build/ <file>.tex
```

**Accessible HTML output (via make4ht):**
```bash
make4ht -s -l -c se423 -d out/ <file>.tex "mathml"
```

**Figures → SVG:**
```bash
latexmk -pdflua Lectures/Figures/<figure>.tex
dvisvgm --pdf --no-fonts --output=<output>.svg <figure>.pdf
```

**Alternative (no local install):** Import the project into Overleaf — the repo supports Overleaf sync. Set the compiler to **LuaLaTeX**.

**Slide figures** (a uv script, stdlib only; `mutool` from mupdf-tools refreshes SVG PNG fallbacks):
```bash
uv run tools/sync_deck_figures.py extract           # register new pictures, drop deleted ones
uv run tools/sync_deck_figures.py auto --base HEAD  # copy each change in the direction it was made
uv run tools/sync_deck_figures.py sync | pull       # force files -> decks | decks -> files
uv run tools/sync_deck_figures.py check             # exit 1 if a picture differs from its file
uv run tools/sync_deck_figures.py decks <files>     # which decks use these source files
sh tools/install-hooks.sh                            # pre-commit hook: extract + auto, stages results
```

**Repo card:** `uv run .github/assets/make_repo_card.py` (rewrites `repo-card.svg` + `.png`; ~300 layout/accessibility checks must pass).

**Local TeX caveat:** Debian/Ubuntu's packaged TeX Live (2023) lacks `luaotfload` unless `texlive-luatex` is installed, and its LaTeX kernel is too old for the PDF/UA tagging in the homeworks. Use TeX Live 2026 (as CI does) to reproduce CI builds.

`pdf-list.txt` lists every `.tex` file the CI compiles (syllabus, homeworks, LabVIEW, labs). All files in that list must build without errors before a PR is merged.

## Architecture

### LaTeX Document System

All LaTeX documents share a common preamble via `\input{header}` at the top of every `.tex` file. Key shared files:

- **`header.tex`** — imports all packages, defines UIUC color palette, custom macros (`\MakeAssignmentTitle`, `\Ex`), and the `\ifSEhtml` flag for PDF-vs-HTML conditional compilation
- **`icons.tex`** — icon/symbol definitions used across documents
- **`timline.tex`** — shared course timeline header included in assignments
- **`fontsetup.tex`** — sets the course typeface, Atkinson Hyperlegible Next, from the OTFs vendored in `fonts/` (SIL OFL). Loaded by `header.tex` and by every `Lectures/Figures/*.tex`; needs LuaLaTeX (no-op under pdfLaTeX/tex4ht). Builds must run from the repo root so `fonts/` resolves
- **`tools/sync_deck_figures.py`** + **`Lectures/Slides/figures.toml`** — every picture in the decks has a source file in `Lectures/Figures/{svg,png,jpg,gif,ppm}/` (deck-only images in per-deck subfolders); `auto --base REF` copies each change in the direction it was made since REF (slide edited → file, file edited → slide, both → conflict), `sync`/`pull` force a direction, `check` reports drift, `extract` registers new pictures and prunes deleted ones (and their generated files). `tools/git-hooks/pre-commit` (enabled by `tools/install-hooks.sh`) runs extract + auto and stages what they write. Pictures are keyed by slide id + `a16:creationId`, not by `ppt/media` names (PowerPoint renumbers those). Video/audio placeholders (YouTube embeds, sound clips) are not figures and are skipped
- **`se423.cfg`** — tex4ht configuration for accessibility output (overrides inline styles to meet WCAG AA; also sets Atkinson Hyperlegible Next for HTML output)

The `\ifSEhtml` flag switches between `minted` (PDF) and a verbatim fallback (HTML), since `minted` requires shell-escape which make4ht doesn't support in the same way.

### CI Pipeline

`.github/workflows/build-latex.yml` orchestrates the entire build:
1. Detects changed `.tex` / `.pptx` / figure-source files via `tj-actions/changed-files` (incremental builds; a changed figure source also rebuilds the decks that embed it)
2. Builds PDFs with `latexmk -pdflua`
3. Brings decks and figure sources in step (`tools/sync_deck_figures.py auto --base <commit before the push>`; never reverts a slide edit, nothing committed back), then converts PPTX to PDF via LibreOffice headless
4. Converts TikZ figures to SVG via `dvisvgm`
5. Generates accessible HTML via `make4ht`
6. Injects SVG gallery (top-level `Lectures/Figures/svg/*.svg` only) into the site's `index.html`
7. Deploys everything to the `artifacts` branch

Incremental builds only rebuild files that changed: editing `header.tex`, `fontsetup.tex`, `se423.cfg` or `icons.tex` does **not** rebuild existing PDFs/HTML. Trigger the workflow manually (workflow_dispatch) after such changes.

### Site (`site/`)

Static HTML/CSS/JS served via GitHub Pages. Uses Three.js (via import map) for the LIDAR SLAM visualization; its JSX in `site/lidar_slam/src/` is compiled by CI (`site/lidar_slam/build.sh`). The `index.html` gallery is auto-populated by CI from the top-level `Lectures/Figures/svg/*.svg` — do not manually edit the SVG injection block.

## Accessibility checks (`tools/a11y/`)

uv scripts: `lint_latex.py`, `lint_pptx.py`, `check_pdf.py` (veraPDF `ua2`), `check_html.py` (Playwright + pinned, hash-checked axe-core), orchestrated by `run_all.py` with a ratchet against `a11y-baseline.json` (`findings.py`). Findings are keyed by stable locators (file + rule + slide id/picture id or colour scheme), never line numbers. Rules for agents:
- Never add a picture, figure or slide without alt text and (for slides) a real title; never raise counts in `a11y-baseline.json`, only lower them with `--update-baseline` after fixing things.
- CI gates pull requests (`pull_request` trigger) and only reports on `main` (`continue-on-error`), so publishing is never blocked; the deploy step is skipped on PRs.
- Slide PDFs are reported as warnings only until the LibreOffice export is tagged.
- Local veraPDF: set `VERAPDF` to the `verapdf` launcher; CI uses the `verapdf/cli:v1.30.2` image pinned by digest (`--docker`).
- `run_all.py --sarif` also writes the findings as SARIF; CI uploads it to code scanning (category `accessibility`), fingerprinted by the same stable keys.
- `pptx_to_html.py` builds the accessible HTML of each deck (CI publishes `Lectures/Slides/<deck>.html`); equations go OMML → MathML through pandoc.
- Read decks with `deck_reader.py` (python-pptx + XPath, coloraide for colours), never with regexes over XML. Write decks only through `sync_deck_figures.py` (`Deck.save`): python-pptx's save re-serializes every part.

## Python tooling (uv)

Every script is a uv script (PEP 723 header) with `==` pins, `[tool.uv] exclude-newer = "14 days"` (release cooldown) and a committed `<script>.py.lock`. Run scripts with `uv run [--locked] tools/...`, never `python3`/`pip`. When you add or change a dependency: pin it with `==` to a release at least 14 days old, run `uv lock --script <script>.py`, commit the lockfile. A script that imports another script's module must declare that module's dependencies too. Lint/format with `uvx ruff@0.16.9 check .` / `format` (`ruff.toml`); the ruff version is pinned in the workflow and the hook, keep them in step. GitHub Actions are pinned by commit SHA with the version in a comment.

## Typeface (required everywhere)

All material is set in **Atkinson Hyperlegible Next** (Braille Institute, SIL OFL; files in `fonts/`, including SemiBold/ExtraBold for the repo card). Code stays monospace; LaTeX math stays in Latin Modern, and math-only labels in figures (Cambria Math, Computer Modern, math-italic Unicode) keep their math face. When adding or changing anything:

| Material | How |
|---|---|
| LaTeX documents | Nothing extra: `header.tex` → `fontsetup.tex`. Build with LuaLaTeX from the repo root (pdfLaTeX silently falls back to the old font). |
| TikZ figures (`Lectures/Figures/*.tex`) | Put `\input{fontsetup}` right after `\documentclass`; build with `latexmk -pdflua`. |
| HTML output | `se423.cfg` (Google Fonts link + CSS). Keep the font out of monospace classes. |
| Slides | Theme and every Latin text run use the font (Arial/Calibri were replaced). New text boxes must use the theme font. CI installs `fonts/*.otf` before LibreOffice exports PDFs. |
| matplotlib plots | In SE423Animations: `import course_style; course_style.apply()` after any `plt.style.use`/`rcParams` block. |
| Other SVGs (Inkscape, Wikimedia, PowerPoint) | Set non-math text in the font, scale `font-size` so labels keep their original width (Times → ×0.927), then outline: `inkscape in.svg --export-text-to-path --export-type=svg --export-filename=out.svg`. |
| Site pages | Google Fonts `Atkinson+Hyperlegible+Next:ital,wght@0,200..800;1,200..800`; keep the existing mono font for code. |

## Figures in the slides

Every picture on a slide (except the UIUC template logos, listed under `ignore`) has an entry in `Lectures/Slides/figures.toml` pointing to its source file. Either side may be edited: the instructor authors in PowerPoint, plots are regenerated in SE423Animations. Direction is decided from git history, per picture (`auto`).

- Editing a figure file (e.g. regenerating a plot): change it in `Lectures/Figures/`, run `auto --base HEAD` (or let the hook do it), commit the file and the deck.
- Editing in PowerPoint: just save and commit; the hook/`auto` copies the picture into its source file. A picture replaced with another format gets a new source file (`Lectures/Figures/<kind>/<deck>/slideNNN_k.<ext>`) and its manifest entry is repointed.
- New picture: `extract` writes `Lectures/Figures/<kind>/<deck>/slideNNN_k.<ext>` (identical content reuses an existing file) and adds an entry. Deleted picture: `extract` drops the entry and deletes now-unused files in the per-deck folders (those folders are owned by the tool; put hand-made sources elsewhere). Prefer pointing `source` at a well-named file in `Lectures/Figures/svg/`.
- Both sides changed since the base → conflict; resolve with `pull` (slide wins) or `sync` (file wins). Never "fix" a conflict by editing `figures.toml`.
- Entries are keyed by `<slide id>/<a16:creationId>` (fallback `shape-<id>`), which survive saves and slide reordering; `slide =` is informational only.
- When scripting deck edits in tests or tools, write decks with `Deck.save` (keeps zip order/compression) and keep the hook's contract: everything a run writes goes through `written()` so `--written` can stage it.
- Never rename or renumber files in `ppt/media/` by hand, and don't edit decks with scripts that rewrite `[Content_Types].xml` or drop unknown parts: preserve zip entry order and compression (see `Deck.save`).

## LaTeX Conventions

Follow these precisely to keep the build and accessibility pipeline happy:

- **Figures:** always `\begin{figure}[H]`, subfigures always `\begin{subfigure}[b]`
- **Code:** use `minted` (`\begin{minted}{c}` for C, `\mintinline{c}{...}` inline)
- **Arrows:** use `$\rightarrow$`, never `->`
- **List items:** `\item`, not manual numbering
- **Blank lines:** use a `%` comment line as a visual separator before/after `\begin{}`/`\end{}` blocks, not actual blank lines
- **Colors:** use only the named UIUC palette from `header.tex`; do not define new colors
- **Fonts:** never call `\setmainfont`/`\usepackage{helvet}` etc. in a document; the typeface comes from `fontsetup.tex` only
- **New packages:** don't add packages to `header.tex` without discussing it first — the accessibility pipeline and Overleaf compatibility are sensitive to package order

## Branching & Commit Style

Branch naming: `fix/lecture-5-adc-diagram`, `add/homework-3-extra-problems`, `improve/lab-2-spi-explanation`

Commit messages: start with a verb (*Fix*, *Add*, *Update*, *Clarify*) and reference the affected material. Example: `Fix sign error in Lecture 10 transfer function derivation`

## Tagged-PDF pitfalls (PDF/UA-2, `testphase = phase-III`)

Every document in `pdf-list.txt` (syllabus, homeworks, labs) starts with `\DocumentMetadata{... pdfstandard = ua-2, lang = en-US}` and must build on TeX Live 2026. Things that broke builds before and are now guarded in `header.tex`; don't undo them:
- A figure or minted block directly after a list (only a `%` line between, or a minted block right after a nested list inside an `\item`) left tagpdf's paragraph hooks unbalanced ("number of automatic begin … and end … para hooks differ"). `header.tex` adds `\par` before every `figure` and `minted` environment.
- fvextra line breaking (`breaklines`) does not work with tagging: blocks and inline code (`\setmintedinline`) both keep it off; inline breaking recursed forever in Lab2.
- With the new tagged lists, enumitem's `leftmargin=*` and the `before`/`after` keys are rejected; use explicit lengths (see `syllabus.tex`).
- Use `tabular` (with `\multicolumn`, `\rowcolor`), not tabularray's `tblr`: tabularray isn't tagging-aware, so its cells become paragraphs nested in paragraphs (PDF/UA-2 failure; HW2 was converted).
- The PDF title comes from `\CourseCode`, `\CourseName`, `\AssignmentType` and `\HWNum` (`header.tex`); override with `\hypersetup{pdftitle=...}` after `\input{header}` when that doesn't fit (the syllabus does).
