5. Integers Size

The C2000 MCU is a 32-bit CPU, meaning its registers and Arithmetic Logic Unit (ALU) are optimized for 32-bit operations, though it can also handle 16-bit data types. As seen in the Homework the minimum data size is 16-bits!

In most programming classes you will have learned that 1-byte = 8-bits; however, in the C2000, given that TMS320C28x char is 16 bits and the ANSI/ISO (C programming standard) further stipulates that when sizeof is applied to char, the result is 1. So, 1-byte = 16-bits for this system!!!

Lecture notes

This slide, titled "Integers Size," has two paragraphs of text and no figures. The first says the C2000 microcontroller is a 32-bit CPU: its registers and its Arithmetic Logic Unit, or ALU, are optimized for 32-bit operations, though it also handles 16-bit data types. As you saw in the homework, the smallest data size is 16 bits. The second paragraph explains that although you learned 1 byte = 8 bits, on the C2000 the TMS320C28x char is 16 bits. The ANSI/ISO C standard requires sizeof(char) to equal 1, so on this system 1 byte = 16 bits.

Here is why. The C28x memory is addressed in 16-bit words, so the smallest thing the CPU can address is 16 bits. C defines a "byte" as the size of a char, not as 8 bits, so the compiler makes char 16 bits. Everything else is measured in those 16-bit units. On the C28x compiler an int is also 16 bits, so sizeof(int) = 1. A long or a float is 32 bits, so sizeof(long) = 2.

This causes real bugs. If you port code that assumes 8-bit bytes, memcpy lengths, buffer sizes and packed communication data can all come out wrong. You will see this when you send characters over the serial port later in this lecture. Also note that uint8_t is generally not available on this compiler.

Quick check: what does sizeof(float) return on the Red Board? It returns 2.

6. Signed Integers

How do we represent negative numbers in a system that only understands 0 and 1?

What is the problem with just setting a single bit to represent positive or negative?

The problem is that you just use a single bit to define the positive or negative, i.e.

0b101 = -1 vs 0b001 = 1

What happens at 0?

0b100 = -0 vs 0vb000 = 0

Which doesn’t make much sense, we waste a single number for a -0!

Lecture notes

This slide is text only, written as a series of questions and answers about representing negative numbers in binary. It asks: how do we represent negative numbers in a system that only understands 0 and 1, and what is wrong with simply using one bit to mark positive or negative?

On the last slide you saw how many bits the C2000's integer types use. Now we ask how some of those bits can encode a sign. The obvious idea is called sign-magnitude: the left-most bit is the sign (0 for positive, 1 for negative) and the remaining bits hold the size of the number. The slide uses 3-bit examples: 0b101 is -1, and 0b001 is +1. The "0b" prefix just means the digits that follow are binary.

The problem shows up at zero. 0b100 means "negative zero" and 0b000 means zero. The slide writes the second one as "0vb000," which is a typo for 0b000. Two bit patterns for the same value means one pattern is wasted. With 3 bits you have 8 patterns but can only represent 7 distinct values, from -3 to +3.

There is a second, more practical problem. Ordinary binary addition gives the wrong answer. Add 0b001 (+1) and 0b101 (-1) and you get 0b110, which sign-magnitude reads as -2, not 0. The CPU would need extra logic just to handle signs.

Quick check: with 3-bit sign-magnitude, what bit pattern represents -3? (Answer: 0b111.)

Both problems are what two's complement fixes, which is the topic of the next slide.

7. 2’s Complement (1/2)

This utilizes Modular Arithmetic to derive that:

−x=∼x+1- x\ = \ \sim x + 1

Extremely simple and CPU operation wisely efficient!

Achieves full range of:

[−2N−1,2N−1−1]\lbrack{- 2}^{N - 1},2^{N - 1} - 1\rbrack

Most significant bit ( the left-most bit in this case ), represents the sign (0=positive, 1=negative)

Lecture notes

This slide answers the problem from the previous slide: sign-magnitude wastes a pattern on negative zero. Two's complement is the fix. The slide has four statements. First, it uses modular arithmetic to derive that minus x equals the bitwise NOT of x plus one, written -x = ~x + 1. Second, this is extremely simple and efficient for the CPU. Third, it achieves the full range from minus 2 to the power N minus 1, up to 2 to the power N minus 1, minus 1, written [-2^(N-1), 2^(N-1) - 1]. Fourth, the most significant bit, the left-most bit, represents the sign: 0 is positive and 1 is negative.

Here is why the formula works. An N-bit register wraps around modulo 2^N. Adding x to ~x always gives all ones, which is 2^N - 1. Modulo 2^N, that is the same as -1. So ~x + 1 = -x.

Try it with 3 bits. 1 is 0b001. Inverting gives 0b110, and adding 1 gives 0b111, which is -1. Now try zero. 0b000 inverts to 0b111, and adding 1 gives 0b1000. The carry falls off the end, leaving 0b000. There is only one zero, so no pattern is wasted.

For 3 bits the range is -4 to 3. On the C2000, a 16-bit int spans -32768 to 32767, and a 32-bit long spans -2147483648 to 2147483647.

It is efficient because subtraction becomes addition: a - b = a + ~b + 1. The same adder hardware handles signed and unsigned values.

A common mistake is reading the MSB as only a sign flag. 0b111 is -1, not -3. Also, negating the most negative value overflows back to itself.

Quick check: what is -3 in 4 bits? (Answer: 0b1101.) The next slide links a video walking through more examples.

10. ASCII (1/2)

Remember that everything in the CPU is binary. So how do we define what a `a`, `b`, `<` represents as a character?

The ASCII character set! It is a 7-bit mapping, 0-127, with an 8-bit character extended edition (not the same as UNICODE).

In C a character is a single letter and represented as `x`, you CANNOT use “x” for a character in C, in Python there is no such thing as a char, just strings!

Strings “abcd” in C represent an array of characters char*. The most important character is 0x00 (NULL), which represents a sentence stopper.

In C, a string is a contiguous (where the pointers are sequentially next to each other) block of memory containing ASCII character, terminated with NULL. Without it the CPU would read forever until a segfaul occurs (reading restricted memory)!

Lecture notes

This slide answers a basic question: if everything inside the CPU is binary, how does the processor know that a pattern of bits means the letter a, the letter b, or the less-than sign? The previous slides showed how bits encode integers, signed and unsigned. Characters work the same way: each one is simply an integer with an agreed-upon meaning.

That agreement is the ASCII character set, which the slide links to. ASCII is a 7-bit mapping, so it covers the values 0 to 127. An extended 8-bit edition adds more characters, but that edition is not the same thing as Unicode.

In C, a single character is written in single quotes, such as 'x'. The slide shows these quotes as backticks. Double quotes, as in "x", make a string, not a char, so you cannot use them for a single character. Python has no separate char type at all, only strings, so this distinction often trips up students who come from Python.

A C string like "abcd" is an array of characters, accessed through a char pointer (char*). It is one contiguous block of memory, meaning the characters sit at consecutive addresses. It always ends with the NULL character, value 0x00, which acts as the sentence stopper. So "abcd" actually occupies five characters: a, b, c, d and 0x00.

Without that terminator, string functions keep reading past the end of your data. On a PC this usually ends in a segmentation fault, which happens when the program reads memory it is not allowed to touch. On the Red Board you may simply print garbage.

Quick check: how many bytes does char s[] = "hi"; need? The answer is three.

11. ASCII (2/2)

If there are less than 7 bits, just put 0s in front of the binary representation

https://commons.wikimedia.org/wiki/File:ASCII-Table.svg

Lecture notes

This slide shows the full ASCII table, from the Wikimedia Commons file linked at the bottom (commons.wikimedia.org/wiki/File:ASCII-Table.svg). It lists all 128 codes, decimal 0 to 127, in three column groups. Each row gives the code in decimal, hexadecimal, binary and octal, followed by the character it represents. A note on the left says that if the binary has fewer than 7 bits, you just put 0s in front. For example, decimal 10 is binary 1010, which as a 7-bit code is 0001010.

A few landmarks are worth remembering. Codes 0 to 31 are control characters, not printable symbols. These include NULL at 0, which terminates strings in C, line feed at 10 (hex 0A) and carriage return at 13 (hex 0D). Code 32 (hex 20) is the space. The digits '0' to '9' are 48 to 57, hex 30 to 39. Uppercase 'A' to 'Z' are 65 to 90, hex 41 to 5A. Lowercase 'a' to 'z' are 97 to 122, hex 61 to 7A, exactly 32 above their uppercase partners. Code 127 is DEL.

A common mistake is confusing the character '7' with the number 7. To turn a received digit character into its value, subtract '0'. That is, value = c - '0', so 55 - 48 = 7. You will do exactly this when parsing bytes that arrive over the serial port.

Quick check: what is 'a' - 'A'? It is 32, because the case offset is a single bit, 0x20.

12. printf and sprintf

We want to write content to the output stream ( the stream can be your console output, serial communication, a file, a string ). The function sprintf, outputs to a buffer, printf outputs to the default output stream.

serial_printf(&SerialA,"Num Timer2:%ld Num SerialRX: %ld\r\n",CpuTimer2.InterruptCount,numRXA);

https://en.cppreference.com/w/c/io/fprintf.html

Lecture notes

This slide introduces printf and sprintf. Now that you know a string is a null-terminated array of ASCII characters, the next question is how to build strings that contain your numbers. The slide states the goal: write content to an output stream, which can be the console, a serial port, a file, or a string. sprintf writes into a character buffer you provide, and printf writes to the default output stream.

The example in the middle is the line you use on the Red Board: serial_printf(&SerialA, "Num Timer2:%ld Num SerialRX: %ld\r\n", CpuTimer2.InterruptCount, numRXA). The first argument picks the serial port. The format string holds two %ld placeholders, each replaced by a long integer from the list after it: the Timer 2 interrupt count and the number of characters received. The \r\n at the end is carriage return (13) followed by line feed (10), the ASCII control codes from the last slide. Together they move the terminal cursor to the start of a new line. On the F28379D an int is only 16 bits and a long is 32 bits, so 32-bit counters need %ld.

The table, from cppreference, lists the printf family in stdio.h. Each function returns an int and takes a format string plus a variable number of arguments, shown as three dots. printf writes to standard output. fprintf takes a FILE pointer stream. sprintf takes a char pointer buffer. snprintf, added in C99, also takes a buffer size. C11 adds bounds-checked versions with names ending in _s. Since C99, the pointer parameters are marked restrict.

A common mistake is calling sprintf into a buffer that is too small. It overruns memory without any warning. Use snprintf instead, which never writes past the size you give it. Next, you look at how the format string itself is built.

13. printf and sprint - format

The format options are available here. Given that you need to format you string based on your pattern, the runtime is non-deterministic and printing usually takes a “very long” (in computer speed) time.

A format specifier follows this prototype:

%[flags][width][.precision][length]specifier

/* printf example */

#include <stdio.h>

int main()

{

printf ("Characters: %c %c \n", 'a', 65);

printf ("Decimals: %d %ld\n", 1977, 650000L);

printf ("Preceding with blanks: %10d \n", 1977);

printf ("Preceding with zeros: %010d \n", 1977);

printf ("Some different radices: %d %x %o %#x %#o \n", 100, 100, 100, 100, 100);

printf ("floats: %4.2f %+.0e %E \n", 3.1416, 3.1416, 3.1416);

printf ("Width trick: %*d \n", 5, 10);

printf ("%s \n", "A string");

return 0;

}

Lecture notes

This slide moves from what printf and sprintf do to how you control their output. The text says the full list of format options is at the link on the slide. It also warns that because the function has to parse your pattern and build the string at run time, its execution time is non-deterministic and, in computer terms, very long.

Every format specifier follows one pattern: percent, then optional flags, width, dot precision and length, then a required specifier. In plain text: %[flags][width][.precision][length]specifier. The next two slides break down each field.

Below that is a short C program, the standard printf example. Here is each line with its output.

%c %c with 'a' and 65 prints "a A", since 65 is ASCII uppercase A, as on the ASCII table earlier.

%d %ld prints 1977 and 650000. The l length matches the long argument 650000L.

%10d pads 1977 with spaces to 10 characters. %010d pads with zeros instead, giving 0000001977.

%d %x %o %#x %#o with 100 prints 100, 64, 144, 0x64 and 0144. The # flag adds the hex or octal prefix.

%4.2f %+.0e %E with 3.1416 prints 3.14, +3e+00 and 3.141600E+00.

%*d with 5 and 10 takes the width from the extra argument, so 10 is printed right-aligned in five characters.

%s prints "A string".

On the Red Board this cost matters. Never call serial_printf inside a fast timer or control interrupt. Set a flag there and print from the main loop instead.

Quick check: what does printf("%05.1f", 2.345) print? The answer is 002.3.

Lecture notes

This slide breaks down the last two parts of the format prototype: percent, flags, width, dot precision, length, specifier. On the slide, "length" is highlighted in orange and "specifier" in green. An orange arrow points to a small table on the left, and a green arrow points to a large table on the right. Both tables come from cplusplus.com/reference/cstdio/printf.

The right-hand table lists the specifiers, the final character that tells printf how to interpret the argument. Each comes with an example output. d or i prints a signed decimal (392) and u prints an unsigned decimal (7235). o prints octal (610). x and X print hexadecimal in lowercase or uppercase (7fa, 7FA). f and F print decimal floating point (392.65). e and E print scientific notation (3.9265e+2). g and G pick whichever of e or f is shorter. a and A print hexadecimal floating point (-0xc.90fep-2). c prints a character, s a string, and p a pointer address (b8000000). n prints nothing; instead it stores the number of characters written so far through a signed int pointer. The left-hand table shows how a length modifier changes the argument type each specifier expects. With no modifier, d expects int, u/o/x expect unsigned int, f expects double, s expects a char pointer, and p expects a void pointer. hh selects char, h selects short, l selects long, and ll selects long long. j, z and t select intmax_t, size_t and ptrdiff_t. This ties back to our integer-size slides. On the C28x processor in the F28379D, an int is only 16 bits and a long is 32 bits. That is why the serial_printf example on slide 12 uses %ld for the 32-bit interrupt counts.

A common mistake is printing a 32-bit variable with plain %d. The mismatch gives you garbage or wrapped values, and it can scramble every argument that follows. Quick check: which format would you use for an unsigned 32-bit counter on the Red Board? The answer is %lu.

17. SCI (1/5)

An RS-232 serial port is a standard for serial communication, sending data one bit at a time. It sends specifically 8-bits of data.

SCI is the hardware peripheral inside the C2000 MCU that implements the UART (Universal Asynchronous Receiver-Transmitter) protocol.

The Protocol:

  • Asynchronous: No shared clock wire. Timing relies on agreed-upon Baud Rate.
  • Frame: Start Bit (Logic 0) → Data Bits (LSB first) → Stop Bit (Logic 1).

init_serialSCIA(&SerialA,115200);

Lecture notes

This slide defines SCI, the serial peripheral you use throughout the course. The slide text says that an RS-232 serial port is a standard for serial communication that sends data one bit at a time, specifically 8 bits of data per character. SCI, the Serial Communications Interface, is the hardware peripheral inside the C2000 microcontroller that implements UART, the Universal Asynchronous Receiver-Transmitter protocol. Below that, the protocol is summarized in two points, followed by one line of code: init_serialSCIA(&SerialA,115200);. A blue arrow points from the words "Baud Rate" down to the number 115200 in that call.

"Asynchronous" means there is no shared clock wire. The sender and receiver each keep their own time, so both must agree in advance on the baud rate, the number of bits sent per second. The function call sets SCI-A to 115200 baud, so each bit lasts 1/115200 seconds, about 8.68 microseconds.

Each character travels as a frame. The line idles at logic 1. A start bit at logic 0 tells the receiver that a frame is beginning. The 8 data bits follow, least significant bit first, and then a stop bit at logic 1 returns the line to idle. With 10 bits per character, 115200 baud carries at most about 11,520 characters per second. That number matters when you decide how much text to print inside a fast loop.

A common mistake is a mismatched baud rate between the board and your terminal program. When the rates differ, you see garbage characters instead of your text.

The next slide shows this frame as a timing diagram.

18. SCI (2/5)

Lecture notes

This slide shows Figure 19-3 from the TI reference manual, "Typical SCI Data Frame Formats." It has two timing diagrams of a single frame on the serial line. In both, the line sits high while idle. It drops low for one start bit, then carries eight data bits in order: LSB, bits 2 through 7, then MSB. After the data comes an optional parity bit, and finally a high stop bit returns the line to idle.

The top frame is labeled idle-line mode, normal nonmultiprocessor communication. This is the ordinary point-to-point case, like your Red Board talking to your PC.

The bottom frame is address-bit mode. It inserts one extra bit, labeled Addr/data, after the MSB and before parity. An arrow labeled "Address bit" points to it. That bit tells every listener on a shared line whether the frame holds an address, which selects a device, or plain data.

This is the frame from the last slide, drawn out bit by bit. The receiver has no clock wire. It waits for the falling edge of the start bit and then samples each following bit at the agreed baud rate. The stop bit guarantees the line goes high again, so the next falling edge is always visible.

To put numbers on it, use the common setting of 8 data bits, no parity and 1 stop bit. One byte then takes 10 bit times. At 115200 baud, as in init_serialSCIA(&SerialA,115200), each bit lasts about 8.68 microseconds, so you get about 11520 bytes per second.

A common mistake is mismatched settings. If the baud rate, parity or stop bits differ between the two ends, every byte arrives as garbage.

This slide shows TI's Figure 3-10, the internal block diagram of one CPU-Timer on the F28379D. Red arrows label the logic gates: two OR gates at the top, an AND gate on the left, and a NOT bubble on one of the AND gate's inputs. Having seen what an interrupt is, you now see the hardware that generates one at a precise rate.

Start at the left. SYSCLKOUT is the system clock, for example 200 MHz. It feeds an AND gate whose other input is TCR.4, the Timer Stop Status bit in the Timer Control Register, passed through a NOT bubble. Clock pulses therefore reach the timer only while TCR.4 is 0. The timer does nothing until software starts it, which in practice means clearing this stop bit.

The pulses go to the 16-bit prescale counter, PSCH:PSC. It counts down and generates a borrow when it underflows. On each borrow it reloads from the 16-bit divide-down register, TDDRH:TDDR, which sets how much the incoming clock frequency is divided. The prescaler slows time down so the main counter runs at a manageable speed.

Each prescaler borrow decrements the 32-bit counter, TIMH:TIM. When TIM reaches zero, three things happen: a borrow occurs, the interrupt TINT is generated (the overbar means it is active low), and the counter reloads from the 32-bit period register, PRDH:PRD. Then the cycle repeats.

The OR gates force both reloads on a Reset or a Timer reload.

Because the counters count from the reload value down through zero, the interrupt period = (PRD + 1)*(TDDR + 1)/SYSCLKOUT. For example, with TDDR = 0 and PRD = 199999 at 200 MHz, you get one interrupt every 1 ms.

The PIE, or Peripheral Interrupt Expansion, is an interrupt router. It takes the many peripheral interrupts and maps them onto the 12 CPU interrupt vectors. Timer 0 goes through the PIE because it is commonly used for application-level tasks, and the PIE gives it prioritization and masking.

The software consequence is that using Timer 0 takes four steps. You enable the timer interrupt, enable the PIE group, enable the CPU interrupt, and acknowledge the PIE inside the ISR. On this chip TINT0 is in PIE group 1. That makes Timer 0 ideal for control loops, scheduling and RTOS ticks.

Timers 1 and 2 bypass the PIE and use the dedicated CPU interrupts INT13 and INT14. They are intended for high-priority system tasks, real-time services and deterministic timing. They have lower latency, are simpler to configure, and are harder to misuse accidentally.

A common mistake is forgetting the PIE acknowledge in a Timer 0 ISR. Without it, the interrupt fires once and never again.

The PIE vector table is a table of function addresses. When an interrupt fires, the CPU looks up its entry in this table and jumps to whatever function address is stored there. That function is the interrupt service routine, or ISR. The ampersand means "address of," so each line says: when this interrupt happens, run this function. The order of the lines does not matter, which is why TIMER2 appears before TIMER1 here.

The vector table lives in protected memory, so you cannot write to it without permission. EALLOW enables writes to protected registers, and EDIS disables them again. If you forget EALLOW, your assignments silently do nothing.

On the previous slide you saw that TIMER1 and TIMER2 connect directly to INT13 and INT14 rather than going through the PIE. They still have entries in this table, though.

Filling in the table only says where to go. It does not turn the interrupt on, and enabling interrupts comes up shortly. Next, you will see the same pattern used for a software interrupt.

So why use a software interrupt at all? Suppose a high-priority ISR, such as a timer ISR, needs some longer, less urgent work done. Instead of doing that work inside the ISR, it can request the SWI and return quickly. In code you trigger it by setting the flag yourself: PieCtrlRegs.PIEIFR12.bit.INTx9 = 1. Group 12 is the lowest-priority group, so this work runs only after more urgent interrupts are serviced.

If your Red Board program suddenly stops inside a default ISR in the debugger, check your pointers and arrays first.

EMIF_ERROR_INT reports a timing violation or a disconnect on the External Memory Interface to external RAM or Flash. The RAM and Flash correctable-error interrupts mean the ECC (Error Correction Code) logic found a flipped bit and fixed it. The ISR usually just logs these events for predictive maintenance. RAM_ACCESS_VIOLATION_INT means code tried to write to a protected memory region.

SYS_PLL_SLIP_INT and AUX_PLL_SLIP_INT mean the Phase Locked Loop, the clock generator, has lost lock, so the CPU clock is unstable. PWM must stop immediately to protect the power electronics, which is the same safety idea as the trip zones on the actuation slide. Finally, the FPU overflow and underflow interrupts flag results beyond the IEEE-754 floating-point limits, producing plus or minus infinity or NaN (not a number).

Next, you look at interrupts from the CPU's helpers: DMA, inter-processor communication and the accelerators.

36. Interrupts – CPU Accelerator

DMA_CH1_INT through DMA_CH6_INT:

Direct Memory Access. Triggers when a large block of memory (e.g., an ADC buffer) has been moved without CPU intervention.

IPC0_INT through IPC3_INT:

Inter-Processor Communication. This device is Dual Core (CPU1 and CPU2). These interrupts are the "phone lines" allowing CPU1 to signal CPU2.

VCU_INT:

Viterbi Complex Unit. An accelerator for vibration analysis (FFT) and communications encoding.

Lecture notes

This slide, titled "Interrupts – CPU Accelerator," moves from the error interrupts on the previous slide to interrupts raised by hardware that offloads work from the main CPU. It lists three groups.

The first group is DMA_CH1_INT through DMA_CH6_INT, for Direct Memory Access. A DMA channel is a small hardware engine that copies blocks of data from one memory location to another while the CPU does other work. For example, it can fill an array with ADC samples. When the whole block has been moved, the channel raises its interrupt. Your code then processes a full buffer at once instead of being interrupted for every single sample. There are six channels, so six independent transfers can run.

The second group is IPC0_INT through IPC3_INT, for Inter-Processor Communication. The F28379D is dual core, with CPU1 and CPU2. The slide calls these four interrupts the "phone lines" that let CPU1 signal CPU2. One core might set a flag to say "new data is ready in shared memory," and the other core's ISR picks it up. In this course you mostly run code on CPU1, but you should know the second core exists.

The last item is VCU_INT, for the Viterbi Complex Unit. This is an accelerator for vibration analysis (FFT) and communications encoding.

Quick check: why would you rather take one DMA interrupt per 256 samples than one ADC interrupt per sample? Because each interrupt costs CPU time to enter and leave the ISR, so fewer interrupts leave more time for your control loop.

Next, we look at a more powerful accelerator, the CLA floating-point engine.

37. Interrupts – CPU Accelerator – CLA ( floating point engine )

CLA_OVERFLOW_INT / CLA_UNDERFLOW_INT:

Mathematical errors specifically within the CLA core.

CLA1_1_INT through CLA1_8_INT:

The Control Law Accelerator (CLA) is an independent 32-bit floating-point math engine. Called once a floating point operation is done.

Lecture notes

This slide covers the interrupts that belong to the Control Law Accelerator, or CLA, on the F28379D. It lists two groups. The first is CLA_OVERFLOW_INT and CLA_UNDERFLOW_INT, described as mathematical errors specifically within the CLA core. The second is CLA1_1_INT through CLA1_8_INT. The CLA is described as an independent 32-bit floating-point math engine, and these interrupts are called once a floating-point operation is done.

The CLA is a small second processor that sits beside the main C28x CPU and does only floating-point math. You give it short pieces of code called tasks, and it runs them in parallel with the CPU. The "operation is done" on the slide means one of these tasks has finished. There are eight task slots, which is why there are eight interrupts, numbered 1 through 8. When task n finishes, CLA1_n_INT tells the main CPU that results such as a new control output are ready to read.

This matters for feedback control. A typical use is to let the CLA run the control law, for example computing a PWM duty cycle from an ADC reading. The main CPU then stays free for serial communication and other housekeeping.

The overflow and underflow interrupts are the CLA's version of the FPU_OVERFLOW_INT and FPU_UNDERFLOW_INT from the errors slide. They fire when a result is too large or too small to represent in IEEE-754 single precision. The CLA has its own math hardware, so it needs its own error flags.

A quick check: if the CLA divides by a value that has drifted very close to zero, which of these interrupts might you see?

Next, we look at interrupts for high-speed peripherals.

38. Interrupts – High-Speed Peripherals

UPPA_INT: Parallel Interface Communication

This is a high-speed, multi-channel parallel bus often used to interface with high-speed ADCs or FPGAs

Lecture notes

This slide, titled "Interrupts – High-Speed Peripherals," lists one interrupt source. In bold it reads UPPA_INT, described as Parallel Interface Communication. Below that, the slide explains that this is a high-speed, multi-channel parallel bus often used to interface with high-speed ADCs or FPGAs. There are no figures.

UPP stands for Universal Parallel Port, and the "A" means it is the first instance of that module. Compare it with the SCI serial port from earlier in this lecture. SCI sends one bit at a time over a single wire. A parallel port sends several data bits at once on separate lines, all clocked together, so its throughput is much higher.

That speed is why you would pair it with an external high-speed ADC that produces samples faster than a serial link can carry them. You would also use it with an FPGA that does custom preprocessing before handing data to the microcontroller.

UPPA_INT is how the module tells the CPU that something needs attention, such as a completed block of data. This follows the same idea as the DMA interrupts two slides ago: hardware moves the bulk data, and the CPU is only interrupted when there is something to act on. The CPU never has to poll the bus.

As a quick check, ask yourself why polling a fast parallel bus in a loop would hurt your control code.

Next, we look at the PIE table's reserved slots and the user-defined software interrupts.

39. Interrupts – Placeholders & User Definitions

PIE1_RESERVED_INT through PIE88_RESERVED_INT:

The hardware architecture allocates a 12×1612 \times 16 grid, but not every slot is connected to a peripheral in this specific chip. These must be mapped to a "Default ISR" that essentially does nothing, to prevent system crashes if noise triggers a phantom interrupt.

USER1_INT through USER12_INT:

These are software traps. You can trigger these manually in code using the assembly instruction TRAP #20. They are often used by RTOS kernels to implement system calls.

Lecture notes

This slide covers two groups of entries in the interrupt vector list that are not tied to any real peripheral: reserved placeholders and user-defined software traps.

The first heading reads PIE1_RESERVED_INT through PIE88_RESERVED_INT. The Peripheral Interrupt Expansion (PIE) block is laid out as a 12 by 16 grid: 12 groups of 16 channels, or 192 possible slots. The F28379D does not connect a peripheral to every slot, so the unused ones are reserved. These still need a valid address in the vector table, so they are mapped to a "Default ISR," a harmless handler that essentially does nothing. If electrical noise or a configuration mistake triggers a phantom interrupt, the CPU lands somewhere safe instead of jumping to a garbage address and crashing.

The second heading reads USER1_INT through USER12_INT. These are software traps: interrupts you trigger on purpose from code rather than from hardware. On the C28x, the assembly instruction TRAP #20 triggers USER1. Real-time operating system (RTOS) kernels often use traps like these to implement system calls, where application code asks the kernel for a service and the CPU switches cleanly into the kernel's handler.

In SE 423 you will rarely touch either group directly, because the provided project code already fills the vector table. Recognizing these entries keeps them from confusing you when you scroll through the full list.

Quick check: why not leave the reserved vectors empty?

40. Interrupts – Debugging

DATALOG_INT (Datalogging Interrupt):

Used primarily by TI's data-logging modules to trigger a capture of internal variables at a specific sample rate. Helpful for logging data for visualization.

EMU_INT:

Triggered by the on-chip debug logic (JTAG). This handles hardware breakpoints or software "Halt" commands. It allows the CPU to enter a suspended state while maintaining the integrity of the peripheral registers.

Lecture notes

This slide, titled "Interrupts – Debugging," closes our tour of the interrupt vector table with two entries that exist to support development rather than your application. It has two short text sections and no figures.

The first is DATALOG_INT, the datalogging interrupt. The slide explains that TI's data-logging modules use it to trigger a capture of internal variables at a specific sample rate. That is helpful when you want to log data and visualize it later, for example plotting a controller's error over time.

The second is EMU_INT, the emulation interrupt. It is triggered by the on-chip debug logic, which you reach through JTAG, the standard debug port that Code Composer Studio uses to talk to the Red Board. EMU_INT handles hardware breakpoints and software "Halt" commands. It lets the CPU enter a suspended state while the peripheral registers stay intact, so you can inspect them exactly as they were when the CPU stopped.

In practice, every time you hit a breakpoint or press Suspend in Code Composer Studio, this mechanism is doing the work. You rarely write code for either of these entries yourself.

Keep one caution in mind for the lab. Halting the CPU does not automatically freeze the outside world. Depending on how a peripheral is configured, its timer or PWM output may keep running while the CPU is stopped. If a motor is spinning when you hit a breakpoint, it may keep spinning, so be careful when you debug with actuators connected.
