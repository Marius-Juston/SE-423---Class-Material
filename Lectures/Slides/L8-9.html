Lecture notes

This slide has the title "FFT Code" and contains only text, no figures or code. It reminds you that you just watched a couple of videos about what a Fourier transform is and what the FFT, the Fast Fourier Transform, is. It then says "Time to implement it!", immediately follows with "Just joking", and explains that smart people have already implemented the algorithms and optimized them to run as efficiently as possible on this specific hardware. The last line notes that this implementation works in C++ and C.

The point is that you do not write an FFT from scratch. A naive discrete Fourier transform of N samples takes on the order of N^2 multiply-adds. The FFT reduces that to about N*log2(N). For a 1024-point transform, that is roughly 10,000 operations instead of about a million. A hardware-tuned library goes further by using the F28379D's floating-point unit and precomputed sine and cosine tables, called twiddle factors. Your job is to set up the data correctly and call the library.

The next slides show what that setup looks like. You will see a 1024-point real FFT configured with RFFT_STAGES = 10, which means 2^10 = 1024 points. You will also see buffers placed in specific memory sections and a structure, RFFT_F32_STRUCT, that tells the library where its input, output and twiddle-factor arrays live.

A common mistake is assuming "use the library" means "no thinking required." You still have to understand buffer sizes, memory placement and how to read the output spectrum.

#define RFFT_SIZE (1 << RFFT_STAGES) // 1024

#pragma DATA_SECTION(pwrSpec, "FFT_buffer_2")

Lecture notes

This slide shows the global declarations for the FFT program. The left column is a block of C code; the right column shows the definition of the library's RFFT_F32_STRUCT and its handle type.

At the top, RFFT_STAGES is defined as 10, and RFFT_SIZE is defined as 1 shifted left by 10 bits, written (1 << RFFT_STAGES), which equals 1024. A radix-2 Cooley-Tukey FFT breaks the computation into log base 2 of N stages, so N = 1024 points needs exactly 10 stages of butterfly operations. That cuts the work from order N squared, O(N^2), for a naive discrete Fourier transform (DFT) to order N times log base 2 of N, O(N*log2(N)). That saving is what makes real-time FFTs possible in an embedded control loop.

Each #pragma DATA_SECTION places an array in a named physical RAM block. fft_input goes in "FFT_buffer_1", and the twiddle factors RFFTF32Coef go in "FFT_buffer_2". If both sat in the same block, the CPU would stall on bus contention and need two clock cycles to fetch the two operands. In separate blocks, the DSP core fetches both in one cycle, roughly halving the time spent in the butterfly loops.

pwrSpec holds only RFFT_SIZE/2 + 1, which is 513, values. For a strictly real input, the spectrum at index N minus k is the complex conjugate of the spectrum at index k, so the magnitudes mirror and the upper half adds nothing new. maxpwr and maxpwrindex track the peak bin.

AdcPingBufRaw and AdcPongBufRaw are 16-bit raw ADC buffers for double buffering. The DMA (direct memory access) writes ADC samples into one buffer while the CPU runs the real FFT on the other, and then the two swap. This gives zero dropped samples. The flags pingFFT, pongFFT, pingpongFFT and iPingPong, together with the counter DMAcount, manage that swap.

The struct on the right holds pointers to the input, output, twiddle (CosSinBuf), magnitude and phase buffers, plus FFTSize and FFTStages. hnd_rfft is a pointer to the rfft instance. Next, you hook DMA_ISR into the PIE vector table.

PieVectTable.DMA_CH1_INT = &DMA_ISR;

Lecture notes

This slide shows three lines of C code on a plain white background. The first line is EALLOW, with the comment "This is needed to write to EALLOW protected registers." The second line is PieVectTable.DMA_CH1_INT = &DMA_ISR, with DMA_CH1_INT highlighted in blue. The third line is EDIS, with the comment "This is needed to disable write to EALLOW protected registers."

On the previous slide you saw the prototype __interrupt void DMA_ISR(void). This slide tells the processor to run that function. The PIE, or Peripheral Interrupt Expansion, vector table is a list of function addresses, one for each interrupt source. Writing &DMA_ISR, the address of your function, into the DMA_CH1_INT entry means that when DMA channel 1 raises its interrupt, the CPU jumps to DMA_ISR.

The PIE vector table is EALLOW protected. Critical registers on the F28379D are write-locked so stray code cannot change them by accident. EALLOW unlocks them. EDIS locks them again right after the write.

A common mistake is to leave out EALLOW. The write then fails silently and your ISR never runs. Another is to forget EDIS, which leaves the protected registers open. Mapping the vector is also only one step: the interrupt still has to be enabled in the PIE and CPU interrupt enable registers before it will fire.

Quick check: what happens if DMA channel 1 finishes a transfer but this line was never executed? The interrupt cannot reach your code. That raises the question of what DMA channel 1 is, which the next slides answer.

12. DMA (1/2)

The direct memory access (DMA) module provides a hardware method of transferring data between peripherals and/or memory without intervention from the CPU, thereby freeing up bandwidth for other system functions.

Many times, applications spend a significant amount of their bandwidth moving data,whether it is from off-chip memory to on-chip memory, or from a peripheral such as an analog-to-digital converter (ADC) to RAM, or even from one peripheral to another.

Furthermore, many times this data comes in a format that is not conducive to the optimum processing powers of the CPU.

The DMA module described in this reference guide can free up CPU bandwidth and rearrange the data into a pattern for more streamlined processing.

Lecture notes

This slide is all text, under the title DMA. It defines the direct memory access (DMA) module as a hardware method of moving data between peripherals and/or memory without the CPU's involvement, which frees CPU bandwidth for other work. It then gives the motivation: applications often spend much of their time just moving data, whether from off-chip to on-chip memory, from a peripheral such as the ADC to RAM, or from one peripheral to another. That data also often arrives in a format that is awkward for the CPU to process. The DMA can both offload the copying and rearrange the data into a more convenient pattern. The wording comes from TI's F28379D Technical Reference Manual, which is why it says "this reference guide."

On the last code slide you registered DMA_ISR in the PIE vector table as the DMA channel 1 interrupt. This slide explains why that interrupt exists. Without DMA, every ADC conversion would interrupt the CPU just so it could copy one result into an array. For an FFT you need hundreds or thousands of samples, so that per-sample overhead adds up quickly. With DMA, the hardware copies each ADC result into your buffer automatically. The CPU only hears about it once, through DMA_ISR, after the whole buffer is full.

A common misconception is that the DMA ISR runs once per sample. It runs once per completed transfer block. Keep that in mind when you read the ping pong buffer code coming up. Next, you look at the DMA's specific features: its channels, trigger sources and throughput.

13. DMA (2/2)

DMA features include:

  • Six channels with independent PIE interrupts
  • Each DMA channel can be triggered from multiple peripheral trigger sources independently
  • Word Size: 16-bit or 32-bit (SPI limited to 16-bit)
  • Throughput: 3 cycles/word without arbitration

The DMA has an 8-bit trigger source selection (“255 options”). The trigger sources range from the ADC, XINT, ePWM, Timer interrupts, SPI and more.

Lecture notes

This slide lists the main features of the F28379D's DMA controller. It is all text: a bulleted list of four features, then a sentence about trigger sources.

The first feature is six DMA channels, each with its own interrupt into the PIE, the Peripheral Interrupt Expansion block that routes peripheral interrupts to the CPU. Each channel works as an independent mover that can tell the CPU "I'm done" through its own interrupt.

The second feature is that each channel can be triggered independently from multiple peripheral trigger sources. A trigger is the event that tells the channel to move its next chunk of data. The closing sentence on the slide says the trigger selection is an 8-bit field, quoted as "255 options." The sources include ADC conversions, external interrupts (XINT), ePWM events, CPU timer interrupts, SPI and more.

The third feature is the word size, which can be 16-bit or 32-bit. SPI transfers are limited to 16-bit.

The fourth feature is throughput: 3 clock cycles per word without arbitration. Arbitration happens when two bus masters, such as the CPU and the DMA, want the same memory or bus at the same time and one has to wait. If nothing competes, at the Red Board's 200 MHz clock, 3 cycles is about 15 ns per word, all done without CPU instructions.

On the previous slide you saw why the DMA exists: it moves data so the CPU doesn't have to. Next comes a block diagram showing where these channels and trigger sources connect. After that, the FFT code uses DMA channel 1, triggered by the ADC, to fill sample buffers. Its interrupt is PIE group 7, interrupt 1.

For our FFT, you trace one path. The ADC conversion-complete interrupt triggers DMA channel 1. That channel copies each result register into a RAM buffer, and when the buffer is full it raises DMA_CH1 to the PIE.

15. FFT Code – Ping Pong Buffer (1/3)

__interrupt void DMA_ISR(void) // PIE7.1 @ 0x000DA0 DMA channel 1 interrupt

{

PieCtrlRegs.PIEACK.all = PIEACK_GROUP7; // Must acknowledge the PIE group

//--- Process the ADC data

if(iPingPong == 0) // Ping buffer filling, process Pong buffer

{

// Manage the DMA registers

EALLOW; // Enable EALLOW protected register access

DmaRegs.CH1.DST_ADDR_SHADOW = (Uint32)AdcPongBufRaw; // Adjust DST start address for Pong buffer

EDIS; // Disable EALLOW protected register access

// Don't run ping FFT first time around

if (DMAcount > 0) {

pingFFT = 1;

}

iPingPong = 1;

}

else // Pong buffer filling, process Ping buffer

{

// Manage the DMA registers

EALLOW; // Enable EALLOW protected register access

DmaRegs.CH1.DST_ADDR_SHADOW = (Uint32)AdcPingBufRaw; // Adjust DST start address for Ping buffer

EDIS; // Disable EALLOW protected register access

pongFFT = 1;

iPingPong = 0;

}

DMAcount += 1;

}

Lecture notes

This slide shows the complete DMA channel 1 interrupt service routine, DMA_ISR, which runs the ping-pong buffer scheme. The comment marks it as PIE interrupt 7.1, vector address 0x000DA0.

The first line acknowledges PIE group 7 by writing PIEACK_GROUP7 to PieCtrlRegs.PIEACK.all. If you forget this, the PIE never delivers another group 7 interrupt, and your FFT silently stops after one buffer.

The body branches on the state variable iPingPong. When iPingPong equals 0, the comment reads "Ping buffer filling, process Pong buffer." Inside EALLOW and EDIS, which unlock and relock protected registers, the code writes the address of AdcPongBufRaw into DmaRegs.CH1.DST_ADDR_SHADOW. It sets the flag pingFFT to 1 only if DMAcount is greater than 0, so no FFT runs the first time through. It then sets iPingPong to 1.

The else branch, "Pong buffer filling, process Ping buffer," mirrors this. It loads the address of AdcPingBufRaw into the shadow destination register, sets pongFFT to 1, and sets iPingPong back to 0. Finally, DMAcount increments on every interrupt.

Notice that the code writes the shadow register, not the active one. All shadow registers are copied to the active registers when the DMA starts its next transfer. That means you can safely change the destination while the DMA is busy writing the current buffer.

The ISR does no math itself. It only swaps buffers and raises flags, and the main loop runs the actual FFT. Quick check: why skip the FFT on the very first interrupt? Next, we step back and look at why ping-pong beats a single buffer.

17. FFT Code – Ping Pong Buffer (2/3)

Lecture notes

This slide shows the problem that the ping-pong buffer solves: a single buffer. There are two flowcharts side by side, joined by a large arrow pointing from left to right to show that one phase follows the other. In each flowchart, an analog voltage feeds the ADC, the ADC feeds the DMA controller, and the DMA controller feeds a single data buffer.

The left phase is labeled "Single Buffer Write." The DMA controller writes ADC samples into the data buffer. A faded arrow on the buffer carries the note that no data processing can occur while the buffer is being written.

The right phase is labeled "Single Buffer Data Processing." The buffer is now full, and a solid arrow shows that data processing begins. The link from the DMA controller to the buffer is drawn as a dotted line, because the DMA controller has to wait for processing to finish.

The key idea is that with one buffer, sampling and processing take turns. While the CPU runs the FFT, no new samples are stored, so you get gaps in your signal and lose the steady sample rate the FFT depends on.

This connects to the ISR on the previous slide. There, you write the next buffer address into DST_ADDR_SHADOW rather than the active register. All shadow registers are copied to active registers when the next DMA transfer starts. That is why the DMA can switch buffers without stopping.

Next, you see how alternating between two buffers keeps sampling continuous.

Every panel has the same signal chain from top to bottom: an analog voltage feeds the ADC, the ADC feeds the DMA controller, and the DMA controller branches into two orange buffers labeled Ping and Pong. A solid line marks the buffer DMA is writing to, and a dotted line marks the other one.

In the first panel, labeled Initial State, the DMA controller writes first to the Ping buffer while the Pong buffer is empty. In the second panel, Ping is full and ready for data processing, shown by a green double-headed arrow under it, while DMA writes to Pong. In the third panel the roles swap: DMA writes to Ping again while Pong is processed. The pattern then repeats.

This fixes the problem from the previous slide. With a single buffer, you could either sample or process, not both. Here the ADC never stops, and the CPU always has one complete buffer to run the FFT on. The constraint is that your processing must finish before DMA fills the other buffer, or you overwrite data you have not used yet.

The idea mirrors how shadow registers work: all shadow registers are copied to active registers at a defined moment, so you prepare the next values without disturbing the ones currently in use.

This slide begins the setup code for the FFT example. It configures ePWM7, not to drive a motor, but as a precise timer that tells the ADC when to sample. The code sits between EALLOW and EDIS, which unlock and relock the protected configuration registers.

Reading the code top to bottom:

First, SOCAEN = 0 disables the start-of-conversion A signal (SOCA), and CTRMODE = 3 freezes the time-base counter. This keeps the module from firing while you change its settings.

SOCASEL = 0x2 selects the trigger event: the counter equals the period register, PRD. SOCAPRD = 0x1 generates a SOCA pulse on every first event, so every period produces one trigger.

TBCTR = 0 clears the counter. TBPHS = 0 and PHSEN = 0 set the phase to zero and disable phase loading, since this PWM is not synchronized to any other module.

That is a 10 kHz sample rate, which puts the Nyquist frequency at 5 kHz. Strictly, up-count mode counts from 0 to TBPRD, so the period is (TBPRD+1) ticks. The difference here is negligible.

Finally, SOCAEN = 1 re-enables SOCA, and CTRMODE = 0 unfreezes the counter in up-count mode. The comment notes that CMPA and CMPB are never set, because no PWM output pin is used.

A common mistake is to change TBPRD and forget that the FFT frequency bins depend on this sample rate.

Lecture notes

This slide is all text, under the title "FIR Filter." It asks: why use an FIR filter at all? The answer, in bold, is linear phase. When a signal passes through a filter, different frequencies are often delayed by different amounts of time, which distorts the shape of the signal. FIR filters can be designed to have strict linear phase, meaning every frequency is delayed by exactly the same amount of time, so the signal shape is perfectly preserved.

On the last slide you saw that an FIR filter is just a weighted sum of the current and past N inputs, with coefficients b_k. Here is why that structure is worth caring about. A filter's phase response tells you how much each frequency is shifted. If the phase is a straight line in frequency, phi(f) = -2*pi*f*tau, then every component is delayed by the same time tau. Think of a square pulse: it is built from many sine waves, and if those sines arrive at different times, the edges smear and ring. With linear phase they all arrive together, and the pulse simply shows up a little later.

The design detail the slide skips is that linear phase comes from symmetric coefficients, b_k = b_(N-k). The delay is then N/2 samples. Your 5-point moving average has order 4 and equal weights, so it is symmetric and delays everything by 2 samples. At an example rate of 1 kHz, that is 2 ms.

A common mistake is to think linear phase means no delay. It does not. In a feedback loop on the robot, that delay still matters.

This slide states a single rule with an equation. The text says the Nyquist frequency is the MINIMUM frequency, in bold capitals, that you should sample your signal at. We do not need to save all the history when the robot is running only the running MM\ last states!

Lecture notes

This slide contains only text, no figures. It makes three points. First, now that MATLAB has generated the filter coefficients, you need to implement the actual filter in your code. Second, while the robot is running you do not need to save the entire history of readings, only the last M states. Third, for an M-order filter you only ever need the current reading and the M previous readings.

Here is why. An FIR filter of order M computes each output as a weighted sum: y[n] = b_0*x[n] + b_1*x[n-1] + ... + b_M*x[n-M]. In words, the output at sample n is the current input times the first coefficient, plus each earlier input times its matching coefficient, going back M samples. Inputs older than x[n-M] have no coefficient, so they never affect the output. Memory and computation per sample are therefore fixed, no matter how long the robot runs.

In practice you keep an array of M+1 inputs. Each time a new ADC sample arrives, you shift the old values back one place (or advance a circular-buffer index), insert the new reading, and compute the multiply-and-add sum.

A common mistake is an off-by-one array size. The 21st-order band-pass filter from fir1 on slide 42 returns 22 coefficients, not 21, so both your coefficient array and your sample buffer need 22 entries.
